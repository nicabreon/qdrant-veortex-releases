# Veortex B1 circular-ring comparison

Revision date: 10 November 2026 (WIB). This focused report measures B1 queries at concurrency 64 and 128 against the prior shared-three-CPU results; earlier benchmark reports remain unchanged.

Campaign `ring-b1-20261110t054451z` finished 2026-11-10T06:05:09.035094+00:00; receipt SHA-256 `faecf5b3e9417001fcd7ac5ff070be85faf988227820e8825eed5a1d70308827`.

**Coverage:** 16/16 timing rows accepted. Eight independent accuracy runs each passed 1,024/1,024 queries with ordered Top10 IDs and FP32 scores within 1e-6. Original containers were restored healthy, overlays were removed first, and immutable lower metadata was unchanged.

Both comparisons used three shared CPUs per node, no per-thread pinning, the same validated Go client, the same 3M × 512D SQ8 fixture, and the same B1/C cell. HTTP RPS is successful HTTP requests / elapsed including final drain; query/s is successful queries / elapsed. Latencies cover the whole validated HTTP response. The engine changed from the prior a1 binary to candidate source commit `1bd74d911`; the candidate change targets multi-query explicit batch admission, while the B1 singleton path is unchanged. This report makes no B1 kernel-optimization claim.

Rows are matched by backend, category, and concurrency against the earlier a1 shared-three-CPU B1 rows. Separately, eight historical Native Qdrant 1.20 rows from H0 are included as context and were not rerun. This report requires per-node submitted/completed ring-query deltas to equal 16 warmup queries plus successful timed queries, with zero fallback and zero HNSW calls.

## Method and scope

Current rows used the candidate dynamic-ring engine with three ring workers, separate TopK disabled, a 2 GiB queued-query budget, and three shared CPUs per node. Runtime thread masks and per-node CPU work were observed during every row. The AVX512 VNNI tier required AMX calls to remain zero and VNNI calls positive on all nodes; Auto required positive AMX calls on all nodes.

The prior a1 rows and historical native rows are reused references and were not rerun. The candidate B1 path is unchanged by the multi-query admission fix, so measured differences may reflect run-to-run or engine-build variation and are not attributed to that fix. These single-pass observations do not establish a general performance change.

All 16 current rows have zero request/query errors, HTTP 429s, transport failures/timeouts, protocol errors, and correctness failures; every successful query matched exact client-side Top10 truth. Ring proof is per node and includes warmups. The historical fixture has unknown original gallery-generation seed, but both campaigns use the same stored fixture and independent FP32 oracle.

The shared-CPU observer is version 2. It retains original process utilization and interval tick values, and separately verifies positive same-TID/starttime/stable-name scheduler-runtime deltas within the row window, or strictly in-window newborn-thread runtime. The read cadence remains 200 ms and no extra proc reads were added. The observer and pure evidence validator are SHA-pinned in this report; 24 offline cases verified valid evidence and rejected wrong masks, stale lifetime runtime, identity changes, and invalid interval arithmetic.

This campaign contains 16 fresh timing rows and eight independent accuracy runs. No values are copied from the failed batch-path campaign; the eight native rows are separately labeled historical context.

This candidate ELF is not included in the currently published V45.1 binary release. Its full SHA is recorded below; the earlier release and its historical routing limitations remain unchanged. Native compiler flags remain unmatched, and the reused native rows are context rather than a fresh native run.

# Official native Qdrant 1.20.0 — 9 November 2026

The unmodified official GNU release binary completed this measured scope. Every category passed 1,024 ordered Top10 checks against the same cached exact-FP32 reference used by V45. All timed responses matched it too. The original cluster was restored healthy; read-only lower dataset metadata was unchanged.

**Contract:** 3M × 512D cosine, B1/Top10, three Docker nodes on one KVM VM, three vCPUs per node, one search CPU plus two support CPUs. Custom sharding places exactly 1M points on each node. Scalar SQ8 int8, quantile 1, always in RAM; oversampling 1.2, F32 rescoring on. Metadata exists in all categories. HNSW m=0/payload_m=0. Payload indexes: abis.subject_id (keyword), abis.active (bool), attributes.position (keyword). Each row: 16 untimed warmups, 60-second dispatch; actual elapsed includes drain. RPS = successful completed responses / actual elapsed.

## Limits and reproduction

- Unmodified official native1.20 ELF; external affinity interposer implements one search CPU and two support CPUs per node.
- Stock search closure including TopK/F32 rerank uses its search CPU. V45 moves TopK/rerank to support CPUs; total quota is three CPUs in both cases.
- Same existing SQ8 gallery and cached FP32 reference corpus as historical V45; no HNSW; keyword indexes on abis.subject_id/attributes.position and a bool index on abis.active.
- Official native compiler flags are not matched to V45; historical V45 and this run are not a contemporaneous A/B experiment.
- Initial and timed requests reuse the same 1024-query corpus; not an independent holdout or universal recall guarantee.
- C160 closed-loop is a fixed load point; no maximum-RPS or long stability claim.
- Readiness/permission harness issues were corrected before any measured sweep; no performance row was selected by retry/best-of.

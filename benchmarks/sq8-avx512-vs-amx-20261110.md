## Workload and limits

The fixture contains 3 million normalized 512-dimensional FP32 vectors, with SQ8 used for candidate scanning and FP32 for reranking. HNSW is disabled; cosine search spans three one-million-point shards, subject to each request's filter. Each arm used B1/C128 across three nodes, each with three logical CPUs: one scan/compute CPU and two support CPUs for TopK, rerank, and payload work. Each segment used a 12-candidate cap. The pinned corpus has 1,024 distinct queries per category and metadata in all four categories; the active-only slice is about 90%, and the combined active/position-exclude slice about 9%. The historical fixture seed is unknown; the query corpus is pinned by manifest SHA-256 in the JSON and CSV exports.

This is a fixed C128 comparison, not an exhaustive maximum-throughput search. It is one ordered pass with AVX512 VNNI first and auto second, without repeated ABBA runs. CPUs are VM logical CPUs, not verified physical cores. The comparison does not isolate instruction cost: eligible SQ8 AMX chunks can fuse the score epilogue, while the VNNI path produces raw i32 values followed by separate F32 work.

ISA evidence combines the forced-tier configuration with engine counters; it is not independent instruction-level profiling. Actual DRAM bandwidth was not measured in this campaign.

The original container IDs were restored healthy and the base/donor lower metadata inventory remained unchanged. Full raw client-report hashes and per-node CPU/ISA deltas are in the JSON and CSV artifacts.
